# Job Command Center - AI Repository Summary

## Overview
**Project Name:** Job Command Center  
**Repository:** nam20485/job-command-center-uniform12-a  
**Created:** 2026-02-18  
**Purpose:** Automated LinkedIn job harvesting, scoring, and application management system

## Architecture

### Technology Stack
- **Framework:** .NET 10.0 with C# 12
- **Orchestration:** .NET Aspire (v9.0.0)
- **Database:** PostgreSQL with Entity Framework Core
- **Automation:** Playwright for .NET
- **Frontend:** Blazor Server with MudBlazor

### Project Structure
```
/JobCommandCenter
├── JobCommandCenter.AppHost          # Aspire orchestration entry point
├── JobCommandCenter.ServiceDefaults  # Telemetry, health checks, logging
├── JobCommandCenter.Data             # EF Core DbContext and Migrations
├── JobCommandCenter.Shared           # Domain models and common logic
├── JobCommandCenter.Harvester        # Playwright worker for LinkedIn scraping
├── JobCommandCenter.Web              # Blazor Server management dashboard
└── tests/                            # Test projects
    ├── JobCommandCenter.Shared.Tests
    ├── JobCommandCenter.Data.Tests
    ├── JobCommandCenter.Harvester.Tests
    └── JobCommandCenter.IntegrationTests
```

## Key Components

### 1. AppHost (Orchestration)
- Manages service lifecycle
- Configures PostgreSQL container
- Wires up service dependencies
- **Critical:** Harvester runs as process (not container) for Chrome CDP access

### 2. ServiceDefaults
- OpenTelemetry integration
- Health check endpoints
- Serilog configuration
- Standardized service patterns

### 3. Data Layer
- `JobCommandCenterDbContext` with PostgreSQL
- Entities: Job, ScoringConfig, HistoryLog
- EF Core migrations support

### 4. Shared Domain
- Domain models: Job, ScoringConfig, HistoryLog
- Enums: JobStatus, ApplicationType, ScoringField, MatchType
- Common services and utilities

### 5. Harvester (Worker Service)
- Background service for LinkedIn scraping
- Chrome CDP integration via Playwright
- Humanization delays for anti-detection
- Database persistence

### 6. Web Dashboard
- Blazor Server with MudBlazor UI
- Job listing and management
- Scoring configuration
- Harvester status monitoring

## Configuration

### Environment Variables
| Variable | Description | Default |
|----------|-------------|---------|
| `CHROME_DEBUG_PORT` | Chrome remote debugging port | 9222 |
| `Harvester:SearchCycleDelayMs` | Delay between harvest cycles | 60000 |
| `Harvester:HumanizationEnabled` | Enable humanization delays | true |

### Connection Strings
- `jobcommandcenter-db`: PostgreSQL connection (managed by Aspire)

## Development Setup

### Prerequisites
- .NET 10.0 SDK
- Docker Desktop (for PostgreSQL container)
- Chrome browser with remote debugging enabled

### Running the Application
```bash
# Start Chrome with remote debugging
google-chrome --remote-debugging-port=9222

# Run the Aspire AppHost
cd JobCommandCenter
dotnet run --project JobCommandCenter.AppHost
```

### Database Migrations
```bash
cd JobCommandCenter/JobCommandCenter.Data
dotnet ef migrations add InitialCreate
dotnet ef database update
```
